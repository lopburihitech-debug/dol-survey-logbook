# DOL Survey Logbook — ระบบสมุดช่างรังวัดออนไลน์

ระบบ Phase 1 ที่ใช้งานได้จริง สร้างตาม System Blueprint v2.0 ครอบคลุม: รับเรื่อง รว.19, ข้อมูลแปลงที่ดิน,
มอบหมาย/เปลี่ยน/ย้ายช่าง (พร้อมเก็บประวัติ), Workflow สถานะงานแบบกระชับ (เลือกสถานะรวมถึงถอนจ่ายแล้วได้ตรงจากดรอปดาวน์เดียว),
Dashboard และ Audit Log

## สแตกที่ใช้ และเหตุผล

| ส่วน | เทคโนโลยี | เหตุผล |
|---|---|---|
| Backend | Python (Flask) | เบา อ่านง่าย ดูแลง่าย ไม่ต้องพึ่งบริการภายนอกเยอะ |
| ฐานข้อมูล | SQLite (ไฟล์เดียว) | รันได้ทันทีโดยไม่ต้องติดตั้ง database server แยก เหมาะกับการ deploy ทีละสำนักงาน — ดูหัวข้อ "อัปเกรดสู่ PostgreSQL" ด้านล่างเมื่อพร้อมขยายสเกล |
| Frontend | HTML/CSS/JavaScript ธรรมดา (ไม่มี build step) | ไม่ต้องมี Node.js/build pipeline ใดๆ เปิดใช้ได้ทันที ดูแลง่ายที่สุดเมื่อต้อง deploy ซ้ำไปหลายสาขา |
| Deployment | Docker (1 container ต่อ 1 สำนักงาน) | `docker-compose up` ครั้งเดียวก็ใช้งานได้ ทั้ง API และหน้าเว็บอยู่ในโปรเซสเดียวกัน ไม่มีปัญหา CORS |

โครงสร้างนี้ตั้งใจให้ **ง่ายต่อการบริหารจัดการที่สุด**: ไม่มี build pipeline, ไม่มีบริการภายนอกที่ต้องดูแลแยก,
และขยายไปสาขาอื่นได้ด้วยการ deploy container ซ้ำ (ดูหัวข้อ "ขยายไปหลายสาขา" ด้านล่าง)

## เริ่มใช้งานอย่างเร็ว (Docker — แนะนำ)

```bash
docker-compose up --build
```

เปิดเบราว์เซอร์ไปที่ `http://localhost:8000` ระบบจะสร้างฐานข้อมูลและข้อมูลตั้งต้นให้อัตโนมัติในการรันครั้งแรก

## เริ่มใช้งานแบบไม่ใช้ Docker (พัฒนา/ทดสอบ)

```bash
cd backend
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
python seed.py        # สร้างฐานข้อมูลและข้อมูลตั้งต้น (รันครั้งเดียว)
python app.py          # เปิดที่ http://localhost:8000
```

**ถ้าอัปเดตจากเวอร์ชันเก่า (มีฐานข้อมูล/โฟลเดอร์เดิมอยู่แล้ว):** ต้องรัน `pip install -r requirements.txt` ซ้ำอีกครั้งเสมอ
ก่อนเปิดแอป เพราะเวอร์ชันนี้เพิ่มไลบรารีใหม่ (`reportlab`, `Pillow` — ใช้สร้างภาพ QR code สำหรับฟีเจอร์ยืนยันตัวตน 2 ชั้น)
ไม่ต้องลบฐานข้อมูลเดิมหรือรัน `seed.py` ใหม่ — โครงสร้างตารางใหม่ที่ต้องใช้จะถูกเพิ่มให้อัตโนมัติตอนเปิดแอปครั้งแรก

## สิ่งที่ทำแล้วใน Phase 1 นี้ (ตรงตาม System Blueprint v2.0)

- **Auth & RBAC**: JWT (access 15 นาที + refresh 7 วัน), 5 บทบาท (system_admin, administrator, supervisor, surveyor, citizen — บทบาท citizen เตรียมไว้สำหรับ Phase 3)
- **ฐานข้อมูลครบ 22 ตาราง** ตาม ER Diagram (รวมตารางของ Phase 2-4 ที่ยังไม่มี UI/API เช่น fees, complaints, pdpa_requests, equipment ไว้แล้วเพื่อไม่ต้องแก้ schema ย้อนหลัง)
- **รับเรื่อง รว.19** กรอกเลข รว.19 เองตามแบบฟอร์มกระดาษจริงได้ (ระบบตรวจไม่ให้ซ้ำ) พร้อมช่องวันที่รับเรื่อง/วันที่นัดรังวัด และช่องประเภทงานแบบพิมพ์ค้นหา (autocomplete) จากรายชื่อประเภทงานจริงของกรมที่ดินกว่า 90 รายการ พิมพ์ชื่อใหม่ที่ไม่มีในรายการเพื่อเพิ่มประเภทงานได้ทันที — ระบบคำนวณวันครบกำหนดเป็น**วันทำการ**ให้อัตโนมัติ(ข้ามเสาร์-อาทิตย์และวันหยุดราชการในตาราง `public_holidays`)
- **ข้อมูลแปลงที่ดิน** (โฉนด/เลขที่ดิน/ระวาง/ตำบล-อำเภอ-จังหวัด/พิกัด) พร้อม**ลิงก์โลเคชั่น** (เช่นจาก Google Maps — กดเปิดแผนที่นำทางได้ทันที) และ**รูปภาพประกอบแปลงที่ดิน**สูงสุด 3 รูปต่อเรื่อง (รองรับไฟล์รูปภาพทุกประเภท เสิร์ฟผ่าน endpoint ที่ต้อง login เท่านั้น)
- **มอบหมาย/เปลี่ยน/ย้ายช่างรังวัด** ทำได้ทั้งตอนรับเรื่อง รว.19 ใหม่ (dropdown ในฟอร์ม) และภายหลังจากหน้ารายละเอียดงานได้ตลอดเวลา (ปุ่ม "มอบหมายช่างรังวัด" / "เปลี่ยน/ย้ายช่างรังวัด" — ระบุเหตุผลทุกครั้งที่เปลี่ยน) พร้อม**เก็บประวัติช่างที่เคยรับผิดชอบครบทุกคน** (ใครรับช่วงไหน มอบหมายโดยใคร เหตุผลอะไร) ดูย้อนหลังได้จากส่วน "ประวัติช่างที่เคยรับผิดชอบ" ในหน้างานนั้นๆ
- **เช็คลิสต์ความคืบหน้างาน** ในหน้ารายละเอียดงาน: ผลการรังวัด, ขึ้นรูป, ข้างเคียง, ปิดประกาศ — กดสลับสถานะแต่ละช่องได้ทันที บันทึกทันทีที่กด
- **แผนที่หมุดหลักเขต**: ถ่ายภาพหมุดแต่ละจุดในสนามพร้อมดึงพิกัด GPS จากมือถือ/เบราว์เซอร์ให้อัตโนมัติ (แก้ไขพิกัดเองได้ถ้าคลาดเคลื่อน) เพิ่มได้ไม่จำกัดจำนวนจนครบทุกหมุด แต่ละหมุดแก้ไขพิกัด/ลบทีหลังได้ — พร้อม**แผนที่ตัวอย่างแสดงตำแหน่งหมุดและรูปปิดขอบเขต**ให้เห็นภาพทันทีที่มีหมุดตั้งแต่ 1 จุดขึ้นไป (วาดขึ้นเองในหน้าเว็บ ไม่ต้องเชื่อมอินเทอร์เน็ต/แผนที่ภายนอก) ซูมเข้า-ออกได้ด้วยปุ่ม +/− หรือเลื่อนล้อเมาส์/บีบสองนิ้วบนมือถือ ลากเพื่อเลื่อนมุมมอง และปุ่ม "พอดีหน้าจอ" เพื่อรีเซ็ตกลับมาเห็นหมุดทุกจุดพร้อมกัน (มีเข็มทิศบอกทิศเหนือและมาตราส่วนกำกับ) — **แตะที่ตัวเลขหมุดบนแผนที่**เพื่อเปิดดูรูปที่ถ่ายไว้ของหมุดนั้นทันที พร้อมปุ่ม "นำทางไปหมุดนี้" ที่เปิด Google Maps นำทางตรงไปยังพิกัดของหมุดนั้นให้เลย (สะดวกเวลาช่างต้องกลับไปยังหมุดเดิมในสนาม) — กดปุ่มเดียวเพื่อ**ดาวน์โหลด shapefile** (มาตรฐาน .shp/.shx/.dbf/.prj อ้างอิงพิกัด WGS84 เปิดได้ด้วย QGIS/ArcGIS) ที่ประกอบด้วยชั้นจุดหมุดทุกจุด และชั้นรูปปิดขอบเขตแปลงที่ลากเชื่อมหมุดตามลำดับอัตโนมัติ (สร้างให้เมื่อมีหมุดตั้งแต่ 3 จุดขึ้นไป) — ระบบ generate ไฟล์ shapefile เองแบบ pure-Python ไม่ต้องพึ่งไลบรารีภายนอก
- **Workflow สถานะแบบกระชับ** เปลี่ยนสถานะจากดรอปดาวน์เดียวในหน้าดำเนินการได้ทันที: รอการรังวัด, ถอนจ่ายแล้ว, งดรังวัด, นัดตรวจสอบใหม่, เลื่อนรังวัด, ยกเลิก (พร้อมช่องบันทึกเหตุผลทุกครั้ง) — **ถอนจ่ายแล้ว**คือขั้นตอนสุดท้าย จำกัดสิทธิ์เฉพาะผู้บริหาร/ผู้ดูแลระบบเท่านั้นที่จะเห็นและเลือกตัวเลือกนี้ได้ (บทบาทอื่นจะไม่เห็นตัวเลือกนี้ในดรอปดาวน์เลย) — เรื่องหนึ่งๆ ในระบบนี้เป็นได้แค่ 9 สถานะเท่านั้น: รับเรื่องแล้ว, รอมอบหมาย, มอบหมายแล้ว, รอการรังวัด, งดรังวัด, นัดตรวจสอบใหม่, เลื่อนรังวัด, ถอนจ่ายแล้ว, ยกเลิก (ตัวกรองสถานะในหน้า "รายการงาน" จึงแสดงเฉพาะ 9 สถานะนี้ ตัดสถานะเก่าจาก System Blueprint เดิมที่ไม่ได้อยู่ใน workflow ปัจจุบันแล้วออก เช่น กำลังปฏิบัติงาน/รอตรวจ QC/เสร็จสิ้น — เลือกแล้วจะไม่มีทางพบเรื่องใดๆ เลย จึงไม่แสดงเป็นตัวเลือก)
- **Audit Log** ทุกการสร้าง/แก้ไข/เข้าสู่ระบบ พร้อม before/after data
- **Dashboard** สรุป KPI ตามสิทธิ์ของแต่ละบทบาท (ช่างเห็นเฉพาะงานตน หัวหน้าช่างเห็นเฉพาะสำนักงานตน ผู้บริหาร/ผู้ดูแลระบบเห็นทั้งหมด)
- **ปฏิทินนัดรังวัด** (`calendar.html`) — ปฏิทินรายเดือนแสดงวันนัดรังวัดของทุกเรื่อง (นับจาก `appointment_date`) เลื่อนดูเดือนก่อนหน้า/ถัดไปได้ พร้อมปุ่ม "วันนี้" กลับมาเดือนปัจจุบันทันที แต่ละช่องวันที่แสดงเป็น **ชื่อช่างรังวัด** ที่มีนัดวันนั้น (ไม่ใช่รหัสเรื่อง) เพื่อให้เห็นภาพรวมได้ทันทีว่าวันไหนช่างคนไหนออกงาน — ช่างคนเดียวกันที่มีหลายเรื่องในวันเดียวกันจะรวมเป็นชิปเดียวพร้อมตัวเลขจำนวนเรื่องกำกับ (เช่น "หมู (2)") คลิกแล้วเปิดหน้าต่างรายการของวันนั้นให้เลือกเรื่องที่ต้องการดูก่อน ส่วนช่างที่มีเรื่องเดียววันนั้นคลิกแล้วเปิดป๊อปอัพข้อมูลเรื่องได้ทันที (ผู้ขอ ประเภทงาน ช่างรับผิดชอบ วันนัดรังวัด สถานะ) พร้อมปุ่ม "ดูรายละเอียด" เข้าไปหน้ารายละเอียดเรื่อง — เรื่องที่ยังไม่มอบหมายช่างจะรวมเป็นชิปสีส้ม "ยังไม่มอบหมาย" แยกต่างหากให้สังเกตง่าย วันที่มีช่างมากกว่า 3 คนจะยุบเหลือ "+N คนอื่นๆ" คลิกดูรายชื่อช่างและเรื่องทั้งหมดของวันนั้นได้ — ด้านบนสุดมีการ์ด **"วันนี้ช่างรังวัดออกไปรังวัด"** จัดกลุ่มเรื่องที่นัดวันนี้ตามช่างรับผิดชอบ ให้เห็นภาพรวมได้ทันทีว่าวันนี้ช่างคนไหนออกไปรังวัดเรื่องอะไรบ้าง (ไม่ขึ้นกับเดือนที่กำลังเลื่อนดูอยู่) — ข้อมูลที่เห็นเป็นไปตามสิทธิ์เดิมของแต่ละบทบาท (ช่างเห็นเฉพาะงานตน หัวหน้าช่างเห็นเฉพาะสำนักงานตน ผู้บริหาร/ผู้ดูแลระบบเห็นทั้งหมด)
- **หน้าโปรไฟล์ช่างรังวัด** (`surveyor-profile.html`) — แดชบอร์ดสรุปผลงานรายบุคคล เข้าถึงได้จากการคลิกชื่อช่างในหน้า "ข้อมูลช่างรังวัด" (หรือกดปุ่ม "ดูสรุปผลงานของฉัน" ในหน้า "งานของฉัน" สำหรับช่างรังวัดเอง) แสดง: จำนวนงานทั้งหมด/ค้าง/ถอนจ่ายแล้ว/ยกเลิก, จำนวนเรื่องเกินนัดรังวัด 30/60 วัน, ตารางแยกตามประเภทงาน (ทั้งหมด/ค้าง/เสร็จ), ตารางแยกตามเดือนที่รับเรื่องพร้อมแถบกราฟเทียบสัดส่วน, สรุปเช็คลิสต์ความคืบหน้ารวมทั้ง 4 รายการเป็นแถบสัดส่วน และตารางรายการงานทั้งหมดของช่างคนนั้น — สิทธิ์เข้าดู: ผู้บริหาร/ผู้ดูแลระบบดูได้ทุกคน, หัวหน้าช่างรังวัดดูได้เฉพาะช่างในสำนักงานตน, ช่างรังวัดดูได้เฉพาะโปรไฟล์ของตัวเอง
- **หน้าเว็บใช้งานได้จริงครบ 10 หน้า**: เข้าสู่ระบบ, Dashboard, รายการงาน (ค้นหา/กรองตามสถานะ/กรองตามประเภทงาน (เลือกประเภทเจาะจง หรือแสดงทุกประเภท)/กรองตามช่างรังวัดที่รับผิดชอบ (เลือกช่างเจาะจง หรือเลือก "ยังไม่มอบหมาย" เพื่อดูเฉพาะเรื่องที่ยังไม่มีช่างรับผิดชอบ) พร้อมปุ่ม "ล้างตัวกรอง" รีเซ็ตคำค้นหาและตัวกรองทั้งหมดกลับเป็นค่าเริ่มต้นในคลิกเดียว /รับเรื่องใหม่พร้อมมอบหมายช่าง — มีคอลัมน์ **"ช่างรับผิดชอบ"**, **"วันนัดรังวัด"** และ **"เกินนัดรังวัด"** (ป้าย "เกิน 30 วัน" สีเหลือง / "เกิน 60 วัน" สีแดง นับจากวันนัดรังวัดโดยอัตโนมัติ ช่วยให้เห็นเรื่องที่ค้างนานหลังวันนัดได้ทันทีจากรายการ — งานที่จบแล้ว (ถอนจ่ายแล้ว/ยกเลิก/งดรังวัด/นัดตรวจสอบใหม่/เลื่อนรังวัด) หรือยังไม่มีวันนัดรังวัดจะไม่แสดงป้ายนี้) พร้อมคอลัมน์ **"เช็คลิสต์"** แสดงความคืบหน้าทั้ง 4 รายการ (ผลการรังวัด/ขึ้นรูป/ข้างเคียง/ปิดประกาศ) เป็นป้ายข้อความเต็มต่อแถว (เช่น "ผลการรังวัด: เสร็จ") สีเขียว=เสร็จ/ครบ, สีส้ม=ยังไม่เสร็จ/รอ, สีเทา=ยังไม่ระบุ — เห็นความคืบหน้าและใครรับผิดชอบของแต่ละเรื่องได้จากหน้ารายการโดยไม่ต้องเปิดเข้าไปทีละเรื่อง — คอลัมน์วันที่ในหน้านี้แสดงเฉพาะวันที่ไม่มีเวลากำกับ), รายละเอียดงาน (แก้ไขแปลง/ลิงก์โลเคชั่น/รูปภาพ เช็คลิสต์ความคืบหน้า มอบหมาย/เปลี่ยนช่าง+ประวัติ เปลี่ยนสถานะ ประวัติสถานะ แผนที่หมุดหลักเขต), **ข้อมูลช่างรังวัด** (`surveyors.html`), **โปรไฟล์ช่างรังวัด** (`surveyor-profile.html`), **ปฏิทินนัดรังวัด** (`calendar.html`), **งานของฉัน** (`my-work.html`), **จัดการผู้ใช้งาน** (`users.html`), **บัญชีของฉัน** (`account.html`)
- **ข้อมูลช่างรังวัด**: หน้าทำเนียบช่างสำหรับผู้บริหาร/หัวหน้าช่าง/ผู้ดูแลระบบ — แสดงรหัสพนักงาน ชื่อเล่น ตำแหน่ง สำนักงาน และคอลัมน์ **"งานทั้งหมด" / "งานค้าง" / "งานเสร็จ"** ของแต่ละคน (นับเฉพาะเรื่องที่ช่างคนนั้นเป็นผู้รับผิดชอบล่าสุดอยู่ตอนนี้ ตรงกับตัวเลขในหน้าโปรไฟล์ของช่างคนนั้น) คลิกชื่อช่างเพื่อไปหน้าโปรไฟล์สรุปผลงานแบบเต็ม ผู้ดูแลระบบเพิ่มช่างรังวัดใหม่พร้อมสร้างบัญชีผู้ใช้ในขั้นตอนเดียว หรือแก้ไขข้อมูล/ปิดใช้งานได้จากหน้านี้เลย (สำนักงาน/หัวหน้าช่างเห็นเฉพาะช่างในสำนักงานตน) — **แนบรูปถ่ายประจำตัวช่างรังวัดได้** ตอนเพิ่มหรือแก้ไขข้อมูล (เลือกไฟล์รูปแล้วบันทึกได้เลย) ระบบแสดงเป็นวงกลม avatar หน้าตารางรายชื่อ ถ้ายังไม่มีรูปจะแสดงตัวอักษรแรกของชื่อแทน อัปโหลดรูปใหม่ทับรูปเดิมได้เสมอ (เก็บรูปเดียวต่อคน) — เฉพาะผู้บริหาร/ผู้ดูแลระบบเท่านั้นที่แนบ/เปลี่ยนรูปได้
  - หมายเหตุ: การปิดใช้งานช่างรังวัด (ติ๊กออกจาก "ยังปฏิบัติงานอยู่") จะซ่อนช่างคนนั้นจากทำเนียบและไม่ให้เลือกมอบหมายงานใหม่อีก แต่**ไม่ลบข้อมูลเรื่องเก่าที่เคยรับผิดชอบ**และ**ไม่ตัดสิทธิ์ล็อกอิน**ของบัญชีนั้น — ถ้าต้องการปิดกั้นการล็อกอินด้วยให้ไปปิดใช้งานที่หน้า "จัดการผู้ใช้งาน" แทน
- **จัดการผู้ใช้งาน** (เฉพาะผู้ดูแลระบบ): หน้าเดียวดูบัญชีผู้ใช้ทั้งหมดในระบบ (ทุกบทบาท ไม่ใช่แค่ช่างรังวัด) เพิ่มบัญชีใหม่, แก้ไขชื่อ/อีเมล/เบอร์โทร/บทบาท/สำนักงาน, **ปิด-เปิดใช้งานบัญชี** (ปิดแล้วล็อกอินเข้าระบบไม่ได้ทันที ใช้แทนการลบบัญชี), และ**ตั้งรหัสผ่านใหม่ให้ผู้ใช้คนอื่น**ได้โดยตรง (สะดวกเวลาผู้ใช้ลืมรหัสผ่าน หรือใช้เปลี่ยนรหัสผ่านบัญชีตัวอย่างก่อนใช้งานจริง) มีการป้องกันไม่ให้ system_admin ปิดใช้งาน/เปลี่ยนบทบาทบัญชีของตัวเองจนล็อกตัวเองออกจากระบบ — แต่ละแถวมีคอลัมน์แสดงสถานะ 2FA และปุ่ม **"ปิดการยืนยัน 2 ชั้น"** ให้ผู้ดูแลระบบช่วยปิดแทนได้ทันทีเมื่อผู้ใช้ทำอุปกรณ์ยืนยันตัวตนหายและเข้าระบบไม่ได้เลย (ดูหัวข้อ "การยืนยันตัวตน 2 ชั้น" ด้านล่าง)
- **บัญชีของฉัน** (`account.html`, ทุกบทบาทเข้าได้): หน้าจัดการบัญชีตัวเอง — **เปลี่ยนรหัสผ่านตัวเอง** (ต้องกรอกรหัสผ่านเดิมให้ถูกต้องก่อนเสมอ ต่างจากหน้า "จัดการผู้ใช้งาน" ที่ผู้ดูแลระบบตั้งรหัสผ่านใหม่ให้คนอื่นได้โดยไม่ต้องรู้รหัสเดิม) และ**ตั้งค่า/ปิดใช้งานการยืนยันตัวตน 2 ชั้น (2FA) ด้วยตัวเอง**
- **การยืนยันตัวตน 2 ชั้น (2FA / TOTP)**: เพิ่มความปลอดภัยให้ทุกบัญชีได้ (ไม่บังคับ เปิดเองได้จากหน้า "บัญชีของฉัน") — สแกน QR code ด้วยแอปยืนยันตัวตนทั่วไป (Google Authenticator, Microsoft Authenticator ฯลฯ) หรือกรอกรหัสลับด้วยตนเองก็ได้ หลังยืนยันรหัส 6 หลักครั้งแรกสำเร็จ ระบบจะแสดง**รหัสสำรอง (backup codes) 8 ชุดให้ครั้งเดียว** สำหรับใช้เข้าระบบแทนกรณีทำอุปกรณ์หาย (แต่ละรหัสใช้ได้ครั้งเดียว) — เมื่อเปิดใช้งานแล้ว การเข้าสู่ระบบจะมี**ขั้นตอนที่ 2 ขอรหัส 2FA เพิ่มหลังกรอกรหัสผ่านถูกต้องแล้ว**เสมอ ปิดใช้งานเองได้ทุกเมื่อจากหน้า "บัญชีของฉัน" (ต้องยืนยันรหัสผ่านซ้ำก่อนปิด) หรือถ้าเข้าระบบไม่ได้เลย (อุปกรณ์หายและไม่มีรหัสสำรองแล้ว) ให้ติดต่อผู้ดูแลระบบเพื่อปิดแทนจากหน้า "จัดการผู้ใช้งาน" — ระบบ generate QR code และคำนวณรหัส TOTP เองแบบ pure-Python (มาตรฐาน RFC 6238 เดียวกับที่แอปยืนยันตัวตนทั่วไปใช้) ไม่ต้องเชื่อมอินเทอร์เน็ต/บริการภายนอกใดๆ
- **งานของฉัน**: หน้าสำหรับบทบาทช่างรังวัดโดยเฉพาะ (แทนที่เมนู "งานรังวัด" ทั่วไป) แสดงงานที่รับผิดชอบเป็นการ์ดเหมาะกับการใช้งานภาคสนามบนมือถือ เรียงงานที่ยังไม่เสร็จ/ใกล้ครบกำหนดไว้บนสุด ไฮไลต์งานที่เกินกำหนดด้วยสีแดง
- **Responsive Web Design (Mobile-first)**: ใช้งานได้ลื่นไหลทั้งมือถือ (≤480px), แท็บเล็ต (≤768/900px) และเดสก์ท็อป — เมนูบนสุดยุบเป็นปุ่มแฮมเบอร์เกอร์บนจอเล็ก, KPI grid/ฟอร์ม/ตารางปรับจำนวนคอลัมน์อัตโนมัติ, ตารางที่กว้างเกินจอเลื่อนแนวนอนได้ในกรอบของตัวเอง (ไม่ทำให้ทั้งหน้าล้น), Modal ปรับความกว้างตามจอและเลื่อนแนวตั้งได้เมื่อเนื้อหายาว — ทดสอบจริงด้วย Playwright ที่ 375×667 (มือถือ), 768×1024 (แท็บเล็ต), 1280×900 (เดสก์ท็อป) ยืนยันไม่มี horizontal overflow ในทุกหน้า
- **ดีไซน์ธีมใหม่ (โทนเขียว + ตราสัญลักษณ์หน่วยงาน)**: ปรับชุดสีทั้งระบบจากโทนน้ำเงินกรมท่าเดิมเป็น**โทนเขียว** (`--primary` ใน `frontend/css/style.css`) พร้อมสีทองอ่อนๆ (`--gold`) ใช้แต้มเป็นสีรองล้อกับตราสัญลักษณ์ — เพิ่ม**ตราสัญลักษณ์หน่วยงาน**ที่แนบมา แสดงที่แถบเมนูบนของทุกหน้า (มุมซ้ายบน) และหน้าเข้าสู่ระบบ (โลโก้ใหญ่ตรงกลาง) รวมถึงตั้งเป็น**ไอคอนแท็บเบราว์เซอร์ (favicon)** ทุกหน้า — เปลี่ยนฟอนต์หลักเป็น **"Leelawadee UI"** (ฟอนต์ไทยที่มากับ Windows 10/11 อยู่แล้ว ออกแบบมาสำหรับ UI โดยเฉพาะ อ่านง่ายและดูทันสมัยกว่า Tahoma/Angsana เดิมมาก) โดยตั้ง fallback ไปฟอนต์ระบบอื่นให้อัตโนมัติถ้าเครื่องไหนไม่มีฟอนต์นี้ — **ไม่ได้ดาวน์โหลดไฟล์ฟอนต์หรือโลโก้จากอินเทอร์เน็ตเลย** (ไฟล์โลโก้ทุกขนาดอยู่ใน `frontend/img/` แล้ว) จึงยัง deploy และใช้งานได้ครบแม้เครื่องไม่มีอินเทอร์เน็ตเหมือนเดิม — เพิ่มเงา/มุมโค้ง/เอฟเฟกต์ hover ให้การ์ด ปุ่ม และตารางดูมีมิติทันสมัยขึ้น โดยไม่กระทบโครงสร้างหรือฟังก์ชันการทำงานเดิมแต่อย่างใด (รันชุดทดสอบอัตโนมัติทั้งหมดผ่านซ้ำหลังปรับดีไซน์แล้ว)

ทดสอบผ่าน end-to-end แล้วครบทุก flow หลัก (รับเรื่อง → มอบหมายช่าง → เปลี่ยน/ย้ายช่าง → เพิ่มหมุดหลักเขต+ดาวน์โหลด shapefile → เปลี่ยนสถานะ → ถอนจ่ายแล้ว) รวมถึงการจำกัดสิทธิ์ตามบทบาท (RBAC) และทดสอบ Responsive ที่ 3 ขนาดจอ

## ต่อฐานข้อมูล PostgreSQL ออนไลน์ (ใช้งานได้แล้ว — ไม่ต้องรอ)

ระบบรองรับการต่อฐานข้อมูล PostgreSQL ออนไลน์แล้วในตัว (Railway Postgres, Render Postgres, Supabase, Neon ฯลฯ)
สลับได้ด้วยการตั้งค่า environment variable ตัวเดียวคือ `DATABASE_URL` — **ไม่ต้องแก้โค้ดเลยแม้แต่บรรทัดเดียว**
เพราะ `db_postgres.py` ทำหน้าที่เป็น adapter ที่ครอบ `psycopg2` ให้มี interface เหมือน `sqlite3.Connection` ทุกจุด

- ไม่ตั้งค่า `DATABASE_URL` (ค่าเริ่มต้น) → ใช้ SQLite ไฟล์เดียวตามปกติ ไม่ต้องติดตั้งไลบรารีเพิ่มใดๆ
- ตั้งค่า `DATABASE_URL=postgres://user:pass@host:5432/dbname` → เชื่อมต่อฐานข้อมูลออนไลน์ทันที (ทั้ง schema และ
  seed data จะถูกสร้างให้อัตโนมัติในการรันครั้งแรกเหมือนโหมด SQLite) — ต้องติดตั้ง `pip install -r requirements-postgres.txt`
  เพิ่มก่อน (แยกจาก `requirements.txt` หลักโดยตั้งใจ เพราะผู้ใช้งานทั่วไปแบบ SQLite ไม่จำเป็นต้องใช้เลย)

ดูขั้นตอนตั้งค่าแบบละเอียด (สมัครบัญชี Railway/Supabase, สร้างฐานข้อมูล, หา connection string) ได้ที่ `DEPLOY.md`
หัวข้อ "ต่อฐานข้อมูลออนไลน์" — มีสคริปต์ `backend/check_db_connection.py` ให้รันทดสอบการเชื่อมต่อก่อน deploy จริงด้วย

**หมายเหตุ:** โค้ดฝั่ง PostgreSQL เขียนตามมาตรฐาน `psycopg2` ทั่วไปและผ่านการตรวจสอบ syntax แล้ว แต่ยังไม่ได้ทดสอบ
เชื่อมต่อกับฐานข้อมูลจริงแบบ end-to-end (สภาพแวดล้อมที่พัฒนาระบบนี้ไม่มีอินเทอร์เน็ตขาออกไปยัง Postgres provider
ใดๆ ได้เลย) — แนะนำให้รัน `check_db_connection.py` ยืนยันก่อนใช้งานจริงเสมอ ส่วนโหมด SQLite ผ่านการทดสอบ
end-to-end ครบทุก flow แล้วตามปกติ (ดูหัวข้อทดสอบอัตโนมัติด้านล่าง)

## ขยายไปหลายสาขา

ทุกตารางหลักผูกกับ `office_id` อยู่แล้ว มี 2 แนวทาง:

1. **แยก container ต่อสาขา** (เหมาะสำหรับช่วงเริ่มต้น หรือสาขาที่ต้องการข้อมูลแยกเด็ดขาด): แต่ละสำนักงานรัน `docker-compose up` ของตัวเอง มีฐานข้อมูล SQLite แยกกัน ง่ายต่อการดูแล ไม่กระทบกันหากสาขาหนึ่งมีปัญหา
2. **ฐานข้อมูลกลางเดียว หลายสาขาใช้ร่วมกัน** (แนะนำเมื่อต้องการให้ผู้บริหารเห็นภาพรวมทุกสาขาพร้อมกัน): ตั้งค่า `DATABASE_URL` ตามหัวข้อด้านบนให้ทุก container ชี้ไปที่ฐานข้อมูล PostgreSQL เดียวกัน แล้วสร้างระเบียน `offices` เพิ่มต่อสาขา ระบบ RBAC ที่ scope ตาม `office_id` ไว้แล้วจะช่วยแยกข้อมูลแต่ละสาขาให้อัตโนมัติ

## หมายเหตุด้านความปลอดภัย ก่อนใช้งานจริง

- เปลี่ยน `JWT_SECRET_KEY` ใน `.env` เป็นค่าสุ่มยาวๆ เสมอ (ห้ามใช้ค่าตัวอย่าง)
- เปลี่ยนรหัสผ่านบัญชีทดสอบทั้งหมดก่อนเปิดใช้งานจริง (ทำได้ง่ายๆ จากหน้า "จัดการผู้ใช้งาน" &rarr; ปุ่ม "ตั้งรหัสผ่านใหม่" ของแต่ละบัญชี ไม่ต้องยุ่งกับฐานข้อมูลเอง)
- เพิ่ม HTTPS (reverse proxy เช่น nginx/Caddy หน้า container) ก่อนเปิดให้เข้าถึงจากอินเทอร์เน็ต — **จำเป็นสำหรับฟีเจอร์ดึงพิกัด GPS อัตโนมัติของหมุดหลักเขตด้วย** เบราว์เซอร์อนุญาตให้เว็บดึงตำแหน่ง GPS ได้เฉพาะบน HTTPS หรือ `localhost` เท่านั้น ถ้าช่างรังวัดเข้าใช้งานจากมือถือผ่าน IP ของเครื่องในวง LAN (เช่น `http://192.168.x.x:8000`) เบราว์เซอร์จะปฏิเสธการดึง GPS อัตโนมัติ (ยังกรอกพิกัดเองได้ตามปกติ) — เมื่อ deploy ขึ้นออนไลน์ผ่าน Railway/Render (มี HTTPS ให้อัตโนมัติ) จะใช้งานได้ครบ
- แนะนำให้ผู้ดูแลระบบและผู้บริหารเปิดใช้งาน **2FA** (หน้า "บัญชีของฉัน") เพราะเป็นบัญชีสิทธิ์สูง — ดูรายละเอียดวิธีเปิดใช้งานในหัวข้อด้านบน

## ทดสอบอัตโนมัติ (ทางเลือก)

มีชุดทดสอบ end-to-end ด้วย Playwright หลายไฟล์ใน `tests/` ใช้ตรวจสอบระบบระหว่างพัฒนา:

- `test_ui.py` — flow หลัก (login → สร้างเรื่อง → มอบหมาย/เปลี่ยนช่าง → เช็คลิสต์/รูปภาพ → แผนที่หมุด → เปลี่ยนสถานะ → ถอนจ่ายแล้ว)
- `test_surveyors.py` — หน้าข้อมูลช่างรังวัด + งานของฉัน + หน้าโปรไฟล์ช่างรังวัด (แดชบอร์ดสรุปผลงาน, สิทธิ์เข้าดูตามบทบาท, ปุ่มย้อนกลับ)
- `test_responsive.py` — ทดสอบ 3 ขนาดจอ (มือถือ/แท็บเล็ต/เดสก์ท็อป)
- `test_users.py` — หน้าจัดการผู้ใช้งาน (สร้าง/แก้ไข/ปิดใช้งาน/ตั้งรหัสผ่านใหม่)
- `test_mfa.py` — การยืนยันตัวตน 2 ชั้น (ตั้งค่า, ล็อกอิน 2 ขั้นตอน, รหัสสำรอง, ปิดใช้งานเอง, ผู้ดูแลระบบปิดแทน) และเปลี่ยนรหัสผ่านตัวเอง
- `test_calendar.py` — ปฏิทินนัดรังวัด (เรื่องอยู่ช่องวันที่ถูกต้อง, ช่องวันแสดงชื่อช่างแทนรหัสเรื่อง, ช่างเรื่องเดียวคลิกเปิดป๊อปอัพตรงๆ, ช่างหลายเรื่องรวมเป็นชิปเดียว "(N)" คลิกเปิดรายการของวันก่อน, ปุ่มดูรายละเอียด, "+N คนอื่นๆ" เมื่อวันนั้นมีช่างเกิน 3 คน, การ์ด "วันนี้ช่างรังวัดออกไปรังวัด", เปลี่ยนเดือน)
- `test_cases_overdue.py` — คอลัมน์ "เกินนัดรังวัด" ในหน้ารายการงานรังวัด (ป้าย "เกิน 30 วัน" / "เกิน 60 วัน" นับจากวันนัดรังวัด, ไม่แสดงถ้างานจบแล้วหรือไม่มีวันนัด), ตัวกรองสถานะ (9 สถานะที่เป็นได้จริง), ตัวกรองช่างรังวัด (เจาะจงช่าง / ยังไม่มอบหมาย), ตัวกรองประเภทงาน และปุ่ม "ล้างตัวกรอง" (รีเซ็ตทุกช่องกลับเป็นค่าเริ่มต้นในคลิกเดียว)

รันได้ด้วย:

```bash
pip install -r tests/requirements-dev.txt
playwright install chromium
python backend/app.py &   # เปิด server ไว้ก่อน
cd tests && python test_ui.py   # หรือไฟล์อื่นๆ ข้างต้น
```
