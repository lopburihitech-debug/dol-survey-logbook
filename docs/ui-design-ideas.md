# บันทึกไอเดียปรับปรุง UI (เก็บไว้พิจารณาในอนาคต)

> เอกสารนี้เป็นแค่ "บันทึกไอเดีย" ยังไม่มีการนำไปใช้จริงกับระบบ — สรุปจากการดูตัวอย่างหน้าตา dashboard ระบบ ERM
> (บริหารความเสี่ยงองค์กร) หลายแบรนด์ (ORM Sentinel / LifeGuard ERM / RiskMatrix Pro) ที่ผู้ใช้ระบบส่งมาให้ดูเป็น
> แรงบันดาลใจ เมื่อวันที่ 30-31 สิงหาคม 2569 ไม่ใช่ระบบเดียวกับ DOL Survey Logbook แต่มีแพทเทิร์น UI ที่น่าเอามาปรับ
> ใช้ได้

## ⚠️ ก่อนเริ่มทำจริง — ต้อง backup ก่อนเสมอ

ผู้ใช้ระบบยืนยันไว้ชัดเจนว่าก่อนแตะ UI ตามไอเดียในเอกสารนี้ **ต้อง backup โปรเจกต์เดิมไว้ก่อนทุกครั้ง** เผื่อทำแล้ว
มีปัญหาจะได้ย้อนกลับมาใช้ของเดิมได้ทัน ทำตามขั้นตอนนี้:

1. **สร้าง branch ใหม่ก่อนเริ่มแก้** (อย่าแก้บน `main` ตรงๆ):
   ```
   git checkout -b ui-redesign-แบบร่าง
   ```
   ถ้าทำแล้วพัง กลับไปที่ `main` เดิมได้ทันทีโดยไม่กระทบโค้ดที่ deploy อยู่จริง
2. **หรือถ้าไม่ถนัดใช้ branch** อย่างน้อยสร้าง tag/สำรองที่ commit ปัจจุบันไว้ก่อน:
   ```
   git tag backup-ก่อน-ui-redesign-2569
   git push --tags
   ```
3. **สำรองทั้งโฟลเดอร์แบบไฟล์จริง** (เผื่อกรณีร้ายแรงสุด) — คัดลอกทั้งโฟลเดอร์ `dol-survey-logbook` ไปไว้อีกที่ เช่น
   `D:\Survey Logbook APP\_backup_ก่อน_ui_redesign\` ก่อนเริ่มแก้ไฟล์ CSS/HTML ชุดใหญ่
4. **Railway เก็บประวัติ deployment ให้อยู่แล้ว** — ถ้า deploy เวอร์ชันใหม่แล้วมีปัญหา สามารถกลับไปสั่ง deploy
   เวอร์ชันก่อนหน้าซ้ำได้จากประวัติ deployment บน Railway (ไม่ต้อง push โค้ดใหม่ก็กลับเวอร์ชันเดิมได้) — แต่ควรใช้เป็น
   ทางสำรองสุดท้าย ไม่ใช่แทนการ backup โค้ดตามข้อ 1-3
5. ทำทีละหน้า/ทีละจุดเล็กๆ ทดสอบให้แน่ใจก่อนค่อยขยายไปหน้าอื่น (ตามแนวทางที่ระบบนี้ยึดมาตลอดทั้งเซสชัน) — อย่า
   เปลี่ยนทั้งระบบทีเดียว

## แพทเทิร์นที่น่าสนใจ และแนวทางเอามาปรับใช้กับ DOL Survey Logbook

### 1. การ์ด KPI — ไอคอนวงกลมสี + ป้ายแนวโน้ม
ตัวอย่างต้นแบบ: ไอคอนวงกลมสีทึบ (ฟ้า/ส้ม/ชมพู/น้ำตาล) มุมขวาบนของการ์ด คู่กับป้ายเล็กบอกแนวโน้ม (▲2, ▼12%,
"ปกติ") ตัวเลขใหญ่หนา และบรรทัดอธิบายสีเทาด้านล่าง

**เอามาใช้กับเรา**: การ์ด KPI ใน `dashboard.html` (งานทั้งหมด/งานค้าง/เกินกำหนด/งานเสร็จของช่าง) และการ์ด
"จำนวนสถานะงานทั้งหมด" ที่เพิ่งเพิ่มใน `surveyor-profile.html` — เพิ่มไอคอนวงกลมสีได้โดยไม่กระทบ logic เลย
เป็น CSS + SVG icon ล้วนๆ (ดูรูปแบบ `NAV_ICONS` ใน `js/api.js` ที่มี SVG icon ชุดพร้อมอยู่แล้ว เอามาใช้ซ้ำได้)

### 2. Risk Heatmap 5×5 — ตารางสีไล่โทน + drill-down
ไล่สีเขียว→เหลือง→ส้ม→แดงตามระดับ พร้อมตัวเลขจำนวน + score กำกับในช่อง คลิกช่องเพื่อดูรายการย่อย

**เอามาใช้กับเรา**: ไม่ตรงกับ "risk score" ของเราโดยตรง แต่หลักการ "ตารางสีไล่โทน + คลิก drill-down" ปรับใช้ได้กับ
ตารางสถานะงานแยกตามสำนักงาน×เดือน หรือ ปริมาณงานค้างแยกตามช่างรังวัด×เดือน (ต่อยอดจากกราฟ `backlogTrendChart`
ที่มีอยู่แล้ว)

### 3. แถบแจ้งเตือนด่วน (banner) บนสุดของหน้า
แถบสีแดงเข้มค้างอยู่บนสุด มีปุ่ม CTA ("ตรวจสอบทันที") ดึงความสนใจไปยังงานเร่งด่วนโดยไม่ต้องให้ผู้ใช้ไปหาเอง

**เอามาใช้กับเรา**: เหมาะกับ "งานเกินกำหนด" หรือ "ช่างที่งานค้างเกินเกณฑ์ 30 งาน" (ที่เพิ่งทำ backlog cap ไป) —
ถ้าอยากยกระดับความเร่งด่วนให้เห็นทันทีตอนเข้า Dashboard ไม่ต้องรอเลื่อนดูการ์ด

### 4. Sidebar navigation — จัดกลุ่มเมนู + การ์ดสรุปปักหมุดท้ายเมนู
เมนูซ้ายจัดเป็นหมวดมีหัวข้อคั่น (ภาพรวม/การประเมิน/เฝ้าระวัง/กำกับดูแล/ระบบ) มี badge ตัวเลขบนเมนูที่มีงานค้าง และมี
การ์ดสรุป "รอบประเมินปัจจุบัน" ปักหมุดไว้ล่างสุดของ sidebar เสมอ

**เอามาใช้กับเรา**: ระบบเรายังไม่แนะนำให้เปลี่ยนจาก topbar เป็น sidebar เต็มรูปแบบ เพราะช่างรังวัดใช้งานผ่านมือถือ
เป็นหลัก (sidebar จะกลายเป็นเมนูเลื่อนออกมาบนจอเล็กอยู่ดี ไม่ต่างจาก hamburger menu ที่มีอยู่แล้วมากนัก) — แต่แนวคิด
"การ์ดสรุปปักหมุด" เอาไปปรับกับ dropdown เมนูผู้ใช้ (`.user-menu`) บน topbar ได้โดยไม่ต้องเปลี่ยนโครงสร้างหลัก

### 5. โหมดมืด (dark mode)
ชุดสีเข้มยังคงคอนทราสต์ของสีสถานะ (แดง/เหลือง/เขียว) เหมือนเดิม ไม่ปรับโทนสถานะตามธีม — เป็นหลักการที่ถูกต้องถ้าจะทำ

**เอามาใช้กับเรา**: เป็นงานใหญ่ ต้องแตะทุกหน้า/ทุกไฟล์ CSS ควรวางแผนแยกเป็นโปรเจกต์ของตัวเอง ไม่ควรรวมกับงานปรับ UI
เล็กๆ น้อยๆ อื่น

### 6. Multi-brand skin — ใช้ CSS variable ชุดสีเป็นแกน
เปลี่ยนแค่โลโก้/ชื่อ/ค่าสี primary ตัวเดียวก็เปลี่ยนหน้าตาทั้งระบบได้ (สลับได้ทั้ง ORM Sentinel/LifeGuard ERM/
RiskMatrix Pro จากฐานเดียวกัน)

**เอามาใช้กับเรา**: `css/style.css` มี `--primary` เป็น CSS variable อยู่แล้ว เป็นพื้นฐานใกล้เคียงแนวคิดนี้อยู่แล้ว
ถ้าจะขยายให้ปรับสีได้ง่ายขึ้น ควรรวบชุดสีที่ยังฝังเป็นค่าตรงๆ (hardcoded) ในไฟล์ CSS ให้มาอยู่ในตัวแปรให้ครบก่อน

## ลำดับแนะนำถ้าจะเริ่มทำจริงในอนาคต

1. Backup ตามขั้นตอนด้านบนก่อนเสมอ
2. เริ่มจากจุดเสี่ยงต่ำสุดก่อน: เพิ่มไอคอนวงกลมสีในการ์ด KPI ของ `dashboard.html` หน้าเดียว ทดสอบให้ชัวร์
3. ขยายไปหน้าอื่นที่มีการ์ด KPI แบบเดียวกัน (`surveyor-profile.html`)
4. ค่อยพิจารณาแถบแจ้งเตือนด่วน / ตารางสีไล่โทนแบบ heatmap เป็นลำดับถัดไป
5. Sidebar / Dark mode — เก็บไว้พิจารณาทีหลังสุด เพราะกระทบวงกว้างและมีข้อดี-ข้อเสียที่ต้องคุยกันก่อนเริ่ม
